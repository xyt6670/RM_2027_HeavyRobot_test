> 本文记录最初骨架。当前DR16接收及1ms输入刷新见[DR16类练习](DR16类练习_调用链与验收.md)。Control仍保留骨架；本次不执行电机控制。

## 命名依据

参考北林2025英雄的职责前缀习惯，而非逐字照搬。其实际前缀包括util_、periph_、module_、alg_、app_；本工程统一使用bsp_、device_、control_、app_。原库作者和版权注释保留，文件名不等于函数名，暂不批量改动函数/类的API。

| Keil组 / 物理目录 | 文件前缀 | 负责的事情 |
|---|---|---|
| bsp / User/BSP | bsp_drv_can、bsp_drv_uart | 通信外设、缓冲区、收发与回调 |
| device / User/Device | device_dr16 | DR16协议、摇杆键鼠数据；输入到动作的映射不放这里 |
| device / User/Device | device_motor_dji、device_motor_dm | 电机协议、反馈与可调用的电机控制接口 |
| device / User/Device | device_serialplot | 绘图通信协议 |
| control / User/Control | control_chassis、control_gimbal、control_shoot | 底盘、云台、发射控制；目前均为骨架 |
| control / User/Control | control_alg_pid、control_alg_math | 共用算法支持 |
| app / User/App | app_robot、app_remote | 裸机组织入口、输入映射与整车状态协调；目前主要为骨架 |

Core/HAL/CMSIS/DSP保持厂商目录与名字，不给生成代码加用户层前缀。Build集中保存产物；历史备份、旧日志和旧说明在项目外的_工程归档中可恢复。

## 当前能做什么

1. CubeMX外设初始化后，main调用App_Robot_Init。
2. App_Robot_Init初始化四个空模块并记录时间，不启动CAN电机或UART遥控接收。
3. 主循环反复调用App_Robot_Poll；距上次执行至少10ms时，按实际时间间隔调用输入、底盘、云台、发射Update。
4. Update函数目前只有TODO，不产生电机控制输出。这个轮询入口不是精确定时调度，也未完成执行超时监测。

## 建议开发顺序

1. 冻结旧英雄接线、电机ID/模式、轮序/方向、单位、遥控串口与周期。
2. 在设备状态/对象初始化完成后，注册CAN回调并启动CAN；验证反馈与失联。
3. 按独立文档完成USART3/DR16接收链与有效帧检查。
4. 用固定命令完成四轮解算与闭环，再由app_remote映射遥控指令。
5. 完成云台独立控制，再接跟随；完成摩擦轮和拨弹，再接发射请求。
6. 加应用状态、裁判约束、模块取装流程与故障处理。RTOS可并行学习，当前工程不启用它。

## C/C++边界

控制和App骨架使用.c，头文件有extern "C"保护。CAN、UART、电机、算法与绘图库仍使用C++；Keil按具体文件保留--cpp11选项。C文件不能直接使用C++类，后续应增加C接口桥接，或明确把需要实例化类的实现改为.cpp，不能仅靠改分组解决。

CubeMX重新生成后，检查自定义组、包含路径、各.cpp的编译选项以及Build输出目录是否保留。
